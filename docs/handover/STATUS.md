## Результаты ревью (второй проход, вручную, без агентов)

Проверялось чтением кода, поведение на колонке не проверялось. Многоверсионных прогонов не было.

### 1. Ветка `ops`: блокирующих замечаний нет

- **autoaddr на пути по умолчанию совпадает с `main`:** те же команды `bluetoothctl` через stdin с теми же паузами, тот же 12-секундный скан, цикл раз в 20 с, тот же выбор «самого частого» адреса и те же условия успеха. Заметное отличие одно, задокументированное в докстринге: `config.json` теперь читается и пишется как JSON (отступ 2, `ensure_ascii=False`), а не текстовой заменой; формат файла может измениться, значения те же. Запись атомарная, права исходного файла (0600) сохраняются, `.bak-autoaddr` пишется с теми же правами.
- **Диагностика не пишет в колонку.** `sudo` встречается только в печатаемых подсказках для владельца (`address.sh` внутри heredoc), `links.py` делает только чтение `HCIGETCONNLIST`. Исключение, которое нужно знать: `hfp-keys.sh` меняет **уровень логов WirePlumber** на время прогона (`wpctl set-log-level "N,spa.bluez5.native:…"`) и возвращает его при выходе; это пользовательская настройка, не root.
- **Системные файлы** (`scripts/system/*`) сами нигде не применяются. В `70-minitoo-avrcp-acl.rules` стоит заглушка `USERNAME`; `scripts/system/README.md` предписывает подставить пользователя командой `sed`.
- **Юниты** содержат инструкции переключения и отката. Серверные юниты запускают копии скриптов из `~/.local/bin`; сначала сравнить `diff`'ом.

### 2. `display.py` и `transport.py`: блокирующих замечаний нет

- **Путь по умолчанию** (все новые опции выключены): условие в `present()` эквивалентно прежнему, порядок повторов и пауз тот же, `send_rgb888(rgb)` вызывается без дополнительных аргументов. В транспорте добавлены только: возврат таймаута сокета после ожидания ACK (в обычном случае значение то же), проверка длины адреса (для корректного MAC не срабатывает) и `abort()` для остановки.
- **Известные ограничения опций (не баги):**
  - если кадр Listening с меткой вытеснен более новым кадром, метка теряется, и `listen_preroll` откроет микрофон по таймауту `listen_preroll_max_ms`, а не по факту доставки;
  - если новый разговор начался в пределах `hfp_gate_post_mic_ms` (3 с) после закрытия предыдущего микрофона, ворота задержат кадр Listening, и микрофон откроется по таймауту без показа Listening;
  - проверка SCO делает системный вызов под замком `HfpGate` (короткий, не опасный);
  - если сокет закрыт другим потоком во время ожидания ACK, `settimeout` в `finally` может подменить исходное исключение на `OSError`; обе ошибки обрабатываются одинаково, и это только путь выключения.

### 3. `listen_preroll` и talk-key

- Порядок событий согласован: `press` → SDK вызывает `mic_start`, хук откладывает открытие потока → Listening уходит на колонку → реальный микрофон открывается по первому `read()` → WirePlumber переключает профиль → talk-key (`preroll_wait_sco`) видит SCO и только тогда играет «Говорите». Хуки проверены по исходнику `hermes_gadget/linux/audio.py` (v0.2.0): пока `self.mic` пуст, штатный `read()` не выставляет ошибку `microphone stream stopped`.
- **Найдена и исправлена несостыковка:** display берёт индекс адаптера из `minitoo.hci_dev`, а talk-key всегда использовал `hci0`. Теперь talk-key читает тот же ключ (`_minitoo_hci_dev()`); добавлен тест. Относится только к опции `preroll_wait_sco`, по умолчанию выключенной.
- **Замечание:** `preroll_wait_sco` полезна и без `listen_preroll`: подсказка «Говорите» ждёт SCO, а не играет на A2DP до переключения профиля (возможная причина обрезанного начала, §5.4–5.6). Это гипотеза, на колонке не проверена.
